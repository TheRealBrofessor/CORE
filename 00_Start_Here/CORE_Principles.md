# CORE Principles

These principles govern every note, lab, playbook, and Learning Trail in this vault.

## 1. Defensive-Only

CORE covers cybersecurity from a defensive and verification standpoint: hardening, logging, monitoring, incident response, threat modeling, and OSINT *verification*. It does not include offensive techniques, exploit chains, malware, credential theft, unauthorized access instructions, detection evasion, or real-world targeting workflows.

## 2. Source-Aware

Claims should be traceable. Every topic note ends with a **Sources** section. Where a claim is the author's own interpretation rather than an established fact, the note says so directly instead of implying authority it doesn't have.

## 3. Mark Uncertainty

If something is unverified, disputed, or still being learned, the note says so — in the body text and via `status: draft` in frontmatter. CORE prefers an honest "we're not sure yet" over a confident wrong answer.

## 4. One Concept, One Note

Notes are kept small and focused so they can be linked into multiple paths and trails without becoming unwieldy. If a note is trying to cover two unrelated ideas, it should be split.

## 5. Practical Over Theoretical

Every topic note includes "When To Use It" and "How To Use It Safely" — CORE favors applied understanding over abstract theory for its own sake.

## 6. Markdown-First, Plugin-Free

CORE works with nothing more than a text editor or a bare Obsidian install. No community plugins are required for core navigation.

## 7. Beginner-Accessible, No Hype

Direct, practical, technical language. No filler, no exaggerated claims, no fake authority.
